# 星喚びの島（仮題）：経済・ガチャ設計とレビュー

基本無料のモンスター収集RPG（スマホ向け）について、次の2つを行った成果物です。

1. ゲーム内通貨（コイン／有償・無償の星晶石）と天井付きガチャを含む経済設定JSONを作成し、シミュレーションでインフレと天井の問題を診断・修正しました。
2. 課金設計のデザインレビューを行いました（ダークパターン点検、確率表記の注意点を含む）。

## 結論

### 1. 経済（インフレと天井）

| 問題（v1） | 修正（v2） | 結果 |
|---|---|---|
| **コインのインフレ**：後半の流入/流出比 5.12:1、中央値残高 約90万（日収7日分）。日収は90日で7.6倍になり、レベル上げが「タダ同然」に | 収入の成長を 3%/日 → 1.0〜1.2%/日 に抑制。**進化にコイン費用**（30,000 × 1.06^回数）、**ルーン錬成**（収入の15%）を追加。レベル上げに貯蓄（reserve）を設定 | 流入/流出比 **1.00**、中央値残高 **15,576**（日収の半日分）、日収の伸び 2.1倍。インフレ・消費先の枯渇の検出なし |
| **天井が実質的に機能していない**：SSR 2%で救済なし。300連の交換ptはバナー終了で消える。シミュレーション上、交換の利用者は**全類型で0%** | **SSR 3%（確率上昇なし）、すり抜け後はピックアップ確定、120連で交換、天井pt・保証は次のバナーへ持ち越し** | 狙いの1体：平均 95 → **47連**、最悪 300 → **120連**（¥75,015 → **¥30,006**）。消えるptは0 |
| **狙っても取れない**：狙ったバナーのコア無課金の入手率 22% | 同上 | 入手率 **40%**、90日で 0.93 → **1.70体**（ライト 13% → 23%） |

候補5案のうちv2（案C）を採用しました。最悪ケースは案Eと同じ120連で、それでいて**表示確率がそのまま実際の確率になる**ため、確率表記が最も短く正直になります。

### 2. 課金設計レビュー

- **判定**：v2の数値は「最悪いくらで確定するか」が読める、正直な部類の設計です。残る大きなリスクは数値ではなく、**表記と周辺機能の法務**です。
- **P0（リリース前に必須）**
  - I-1 **確率表**：レアリティ別、ピックアップ個別、天井の条件、実質確率を購入前に表示する（テンプレートはレビューの §5.1）。表示と実装を同じデータから生成し、CIで統計テストする。
  - I-2 **図鑑コンプ報酬**：有料ガチャ限定モンスターの組み合わせ収集を条件にすると、**コンプガチャ（カード合わせ）**に当たりうる。条件から外す。
  - I-3 **有償石**：モデル上、約2万人規模で未使用の有償残高が1,000万円を超える。資金決済法の届出・供託・表示・払戻しに備えて、有償と無償を別台帳で管理する。
  - I-4 **未成年者**：年齢確認と月額の上限を設ける。
- **すぐに直せるもの**：パックの石数を10連の倍数にする（現状の2,850石は端数1,350石が残る）。ガチャ結果画面に課金オファーを出さない。デイリー報酬のさかのぼり受け取り。復刻予定の公表。初心者向けの「選べるSSR」。
- **ダークパターン**：v1にあった「誤認させる確率」「天井ptの消滅（サンクコスト）」は、v2で解消または軽減されました。「価格の不透明化（パックの端数）」は**v2にも残っている**ので要修正です。FOMO・ニアミス演出・Pay-to-Win（凸とPvP）・スタミナの課金スキップは未設計のため「リスクあり」とし、健全な代替案を示しました。

### 3. 次の一手

1. **確率表の理解度テスト**：プレイヤー10人に「最悪で何回・いくらで確定するか」「すり抜けたら次はどうなるか」「期間終了後のptはどうなるか」を聞く。**合格基準は8/10以上が全問正解**。
2. 設計者への確認事項（PvPの有無、図鑑報酬の条件、配信地域と年齢区分、スタミナの石回復、復刻の頻度）。答えによって一部の指摘の深刻度が上がります。
3. ソフトローンチでテレメトリを取り、類型の仮定を置き換えて再実行。交換天井（120 / 150）は、**下げる方向の変更だけ**を前提に A/B テストする。

## 再現方法

```bash
PLUGIN=skills/balance-economy/scripts
python3 $PLUGIN/economy_sim.py config/hoshiyobi_economy_v1.json --out out/v1
python3 $PLUGIN/economy_sim.py config/hoshiyobi_economy_v2.json --out out/v2
python3 scripts/gacha_deep_dive.py config/hoshiyobi_economy_v1.json config/hoshiyobi_economy_v2.json \
    --candidates config/pity_candidates.json --out out/deep_dive
```

## 前提と限界

- 2,000人 × 90日、seed 11。類型の比率、ログイン率、バナー参加率、課金スケジュールはすべて仮定です。課金は固定スケジュールのため、**ガチャ仕様による売上の変化はモデルに含まれません**（v2では1体あたりの課金額がおよそ半分になります。ソフトローンチで ARPPU と課金継続率を確認してください）。
- `economy_sim.py` は v2 にもSSR単体の `NO_HARD_PITY` を出します。これは交換天井を考慮しない判定のためで、v2の最悪ケース（120連）は `gacha_deep_dive.py` の厳密計算で確認済みです。
- 価格（¥610 / ¥4,900 / ¥10,000）は仮の値です。実際のストアの価格帯に合わせてください。
- **法令・規約の記述は法的助言ではありません。** 作業環境でWeb検索が使えず、最新の条文やガイドラインの数値を照合できていません。レビュー内の「要確認」箇所は、リリース前に専門家と最新の規約で確認してください。
