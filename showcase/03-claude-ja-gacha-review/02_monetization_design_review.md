# 星喚びの島：課金設計デザインレビュー (Design Review)

- 対象資料：収益化プラン (Monetization Plan)。具体的には `config/hoshiyobi_economy_v1.json` / `v2.json` と、シミュレーション結果 `01_economy_report.md`
- 想定した目標：スマホ向けの基本無料モンスター収集RPG。狙いの体験 (Aesthetics) は「収集の喜び」と「育成の手応え」。課金は「早く・多く集める」ための便利さとして提供し、無課金でも主要コンテンツを遊び切れる。国内（日本）配信が先で、海外展開の可能性あり。
- 前提：パス・パック・ピックアップガチャ以外の機能（PvP、図鑑報酬、スタミナ、ステップアップ等）は資料に未記載です。モンスター収集RPGとして**一般的に入る可能性が高い機能**として点検し、「リスクあり (At Risk)」と表記しています。

> 法令・規約の記述は 2026年10月時点の一般的な理解に基づくもので、法的助言ではありません。この作業では Web 検索が使えず、最新条文を照合できていません。**「要確認」とした箇所は、リリース前に必ず弁護士・プラットフォームの最新規約で確認してください。**

---

## 1. 判定 (Verdict)

v2の数値設計（SSR 3%、すり抜け後確定、120連交換の持ち越し）は、**最悪ケースが120連（約3万円）で読める、正直な部類のガチャ**です。v1にあった「仕組みはあるのに誰も届かない300連天井」と、「バナー終了で天井ptが消えることによる駆け込み圧力」を取り除けています。

いちばん大きな問題は数値ではありません。**表記と周辺機能に法的リスクが残っている点**です。具体的には次の4つです。
- 確率表の書き方
- 図鑑コンプリート報酬がコンプガチャ（カード合わせ）に当たりうること
- 有償石の資金決済法対応
- 未成年者の課金上限

推奨する次の一手は、**ガチャ画面と確率表のモックを作り、プレイヤー10人に「最悪いくらで確定するか」を答えてもらう理解度テスト**です（§8）。

## 2. 強み (Strengths)：維持すべき点

1. **天井が「到達できる」位置にある**：v2の交換天井は120連、かつ持ち越し可能です。コア無課金も、ゼロから約4.4か月貯めれば届きます（無償石は月約4,100個＝約27連）。v1ではシミュレーション上、交換の利用者が0%でした。天井が飾りから実際のセーフティネットになりました（`01_economy_report.md` §5.2）。
2. **表示確率＝実際の確率**：確率上昇の仕組みを入れていないので、「SSR 3%」がそのまま事実です。確率上昇型（案E）より表記が短く、誤認が起きにくい設計です。
3. **有償石と無償石を設定段階から分けている**：`purchases[].paid` で内訳を持っているので、消費順・未使用の有償残高・払戻し額を最初から計算できます。

## 5. 確率表記 (Odds Disclosure) の注意点

### 5.1 v2 の確率表テンプレート（購入ボタンと同じ画面から1タップ）

```
【星詠みピックアップ召喚】提供割合（1回ごと・10連の各回とも同じ）
  ★5（SSR）  3.000%   うちピックアップ「◯◯」1.500%
                       その他の★5（恒常 N 体）各 1.500% ÷ N
  ★4（SR）  12.000%   （各キャラの割合は一覧を参照）
  ★3        85.000%
■ すり抜け後の保証：★5でピックアップ以外が出た場合、次の★5はピックアップ確定。
  この状態は次回以降のピックアップ召喚に引き継がれます。
■ 交換（天井）：1回ごとに召喚pt 1。120ptで現在のピックアップ1体と交換できます。
  ptは召喚期間が終わっても失われず、次回以降のピックアップ召喚で使えます。
■ 目安：ピックアップ1体の入手までに必要な回数は平均約47回、最大120回
  （星晶石 18,000個。¥10,000パックの単価で約¥30,000相当）。
■ 消費順：無償星晶石 → 有償星晶石の順に消費します。
```

### 5.2 注意点チェックリスト

- [ ] **すべての確率を、購入の前に、同じ画面から**：レアリティ別の合計、ピックアップの個別確率、各キャラの確率（一覧）。Apple App Store（審査ガイドライン 3.1.1）、Google Play（ランダム型アイテムのポリシー）とも購入前の開示を求めている。
- [ ] **見出しの数字と実際を一致させる**：「ピックアップ確率UP！」とだけ書かず、UP後の数値（1.500%）を併記する。「◯倍」と書くなら、何と比べて何倍かを明示する。
- [ ] **保証と天井の条件を数値で**：すり抜け後確定・120pt交換・引き継ぎの有無を文章で明記する。確率上昇型を将来導入するなら、**連ごとの確率表**を出す（実質確率と見出しの確率が乖離するため）。
- [ ] **実質確率も併記**：ピックアップの実質確率は約2.12%（平均47.1連で1体）。「最大で何連・いくら」を書くのは、価格の透明性の点で強く推奨。
- [ ] **10連の特典は別表で**：「10連目SR以上確定」などを入れると10回目だけ確率が変わるので、10回目の表を別に示す。
- [ ] **端数と丸め**：小数点以下3桁で表示し、合計が100%になるようにする。「約」は付けない。
- [ ] **広告・告知・ストアページも同じ基準で**：「SSR確定」「誰でも◯◯」などの表現は、条件（初回限定、ステップ◯など）を同じ視野に入れる。韓国向けに配信するなら、広告にも確率表記が義務（2024年3月〜）。
- [ ] **表示と実装の一致を保証する**：抽選テーブルと表示用の表を**同じデータソース**から生成する。CIで1,000万回の抽選を実行し、カイ二乗検定で表示確率と照合する。抽選ログを保管する（中国向けなら記録保存の義務）。
- [ ] **確率の変更は事前告知**：開催中のガチャの確率を黙って変えない。不具合で修正したときは、影響範囲と補填を公表する。
- [ ] **コンプガチャの禁止**：有料ガチャの組み合わせ収集を報酬条件にしない（I-2）。
- [ ] **業界ガイドラインの確認**：日本オンラインゲーム協会 (JOGA) と CESA の、ランダム型アイテム提供方式に関するガイドライン。提供割合の表示方法や、特定アイテムの入手までに要する金額の目安などを定めている（**現行版の条文と数値は要確認**）。

## 7. 設計者への質問 (Questions for the Designer)

1. **PvPやランキング報酬はありますか？** ある場合、I-6（凸の上限・補正の均一化）の深刻度はP0に上がります。
2. **図鑑報酬の条件に、有料ガチャ限定のモンスターは含まれますか？** I-2の可否がここで決まります。
3. **想定する年齢区分と配信地域は？** 韓国・ブラジル・豪州を含むかどうかで、表記と年齢制限の要件が変わります。
4. **スタミナを石で回復させる予定はありますか？** ある場合、石の需要が増え、v2の前提（コア無課金は月約27連）が崩れます。
5. **復刻の頻度は？** FOMO（I-10）と、持ち越した交換ptの価値に直結します。

## 8. 次のテスト (Next Test)

**ガチャ画面と確率表の理解度テスト**（コスト：S。Figma等のモックで可）
- 対象：ターゲット層のプレイヤー10人（ガチャ経験者6人、未経験者4人）
- 手順：v2のガチャ画面と確率表（§5.1）を見せ、次の3問に答えてもらう
  1. 「ピックアップ1体を**最悪で**何回・いくらで確実に入手できますか？」（正解：120回・約¥30,000）
  2. 「★5がピックアップ以外だったら、次はどうなりますか？」（正解：次の★5はピックアップ確定）
  3. 「この召喚期間が終わったら、貯めた召喚ptはどうなりますか？」（正解：引き継がれる）
- **合格基準**：3問とも正解した人が **8/10 以上**。不合格なら、間違いが最も多かった設問の表現を直して再テストする。
- 同時に行う自動テスト：CIで抽選1,000万回 × 各レアリティを実行し、p値が0.01以上であることを確認（表示と実装の一致）。
