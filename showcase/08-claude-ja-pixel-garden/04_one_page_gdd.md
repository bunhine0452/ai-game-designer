# 04 1ページゲームデザイン（One-Page GDD）—「ドット庭師」（仮）

| 項目 | 内容 |
|---|---|
| **ピッチ** | 荒れた庭園の遺跡で、種を植えて道を開く。ツタは橋に、キノコは跳び台に、ヒマワリは灯りになる。15分で庭をよみがえらせる、見下ろし視点のドット絵パズルアドベンチャー。 |
| **プラットフォーム** | PCのブラウザ（キーボード／マウス）。スマホのタッチ操作は対象外（カットリストを参照） |
| **対象プレイヤー** | 短く穏やかなパズルが好きな人。『Lara Croft GO』『A Monster's Expedition』を遊んだ人。アクションの腕前はいらない |
| **プレイ時間** | 約15分（1セッションで遊び切る）。部屋をクリアするごとに自動で保存 |

## デザインの柱（Design Pillars）
1. **植えると世界が変わる** — 能力は持ち歩かず、地面に残る。「どこに・どの順で植えるか」がパズルの中身になる。
2. **間違えても痛くない** — 死ぬことはない。アンドゥ・リセット・引き抜きで、いつでもやり直せる。
3. **解くと庭がよみがえる** — 解決のご褒美は、部屋に色が戻ること。言葉ではなく色で物語を語る。

## コアループ（Core Loop）
部屋を観察する → 植える場所と順番を仮説として考える → 植える／抜く → 地形が変わる → 道が開く → **開花**（色が戻る）→ 次の部屋へ

## 操作
移動: 矢印キー／WASD ・ 植える／抜く: Space（種は自動で選ぶか、1〜3キーで選ぶ）・ アンドゥ: Z ・ リセット: R ・ マウスでクリックしたマスへ移動もできる

## 仕組み（詳細は 03 を参照）
ツタ＝直進して最大4マスの橋 ／ キノコ＝2マス跳ぶ ／ ヒマワリ＝半径3マスを照らす（R5からは「光の中でしか芽吹かない」）／ 種は部屋ごとに3つ、引き抜くと戻る。

## 内容
6部屋（R1 ツタ → R2 キノコ → R3 ヒマワリ → R4 ツタ×キノコ → R5 ひねり → R6 全部）＋ 導入1シーン ＋ 景色の部屋（ハブ）1つ ＋ エピローグ。日記は3枚。

## アートと音（詳細は 02 を参照）
320×180、16pxタイル、パレットは27色（予約色あり）、操作できる物だけにセルアウトのアウトライン、荒廃・開花・暗闇はパレット差し替えで作る。
音: BGMは3曲（荒廃／暗闇／開花）のループ。効果音は約15種（植える・伸びる・弾む・咲く・開花・×・抜く など）。

## 技術
TypeScript ＋ Canvas2D（エンジンなし。Phaser を使ってもよい）。マップは Tiled の JSON から読み込む。決定的なマス単位のシミュレーションなので、アンドゥは状態のスナップショットのスタックで実装する。静的ホスティング（itch.io／GitHub Pages）で公開。

### 範囲チェックリスト
- ☑ 植物は**3種で固定**（4種目は作らない）
- ☑ 部屋は**6つ**。すべて1画面で、スクロールなし
- ☑ 戦闘・敵のAI・体力の仕組みなし（影虫は逃げるだけの単純な動き）
- ☑ 新しい見た目を手で描かず、**パレット差し替えで3倍に使い回す**
- ☑ テキストは300字以内。翻訳するとしても1日で終わる量
- ☑ マス単位の決定的なシミュレーションで、物理演算なし
- ☐ **最大のリスク: パズルの品質**。部屋の設計36時間は楽観的。R5とR6で設計をやり直すことになる前提で考える
- ☐ **二番目のリスク: 音**。自分で作れないなら、早めに素材を決める

### カットリスト（Cut List、優先順位の低いものから削る）
1. マウスでの移動（キーボードだけにする）
2. 段階的ヒント → 壁画を光らせる1段階だけにする
3. R6の2通りの解き方 → 1通りにする
4. 影虫 → 暗闇と光だけにする
5. スマホのタッチ操作（もともと対象外。要望が多ければ次の版で）
**削らないもの**: アンドゥ／リセット、開花の演出、30秒以内のフック、R5のひねり。

### 最初のマイルストーン（2週間）
グレーボックス（Greybox。色の付いた四角だけで作った仮の画面）で R1・R4・R5 を遊べるようにして、初見のプレイヤー3人に遊んでもらう。**R4の「ツタの上にキノコ」で「なるほど」が起きるか**、それだけを確かめる。起きなければ、絵を描く前にルールを見直す。
